# 左營區完整道路地圖圖層設計

## 目標與範圍

當使用者在 LanePilot 網頁標註工具選擇左營區時，地圖要顯示左營區完整道路網（灰色為未標註的一般路段），以方便組員直接在地圖上挑選並標註道路。未選行政區時不載入任何道路圖層，避免初始載入與地圖互動承受不必要的成本。

本次只增加左營區的資料與按選區載入行為；不改變既有路段清單、搜尋、篩選與標註任務的行政區範圍。

## 資料與載入設計

- 使用既有私有輸出中的左營區 shard：`area/4212533`（2351 個路段、1519 個路口），同步其 segment 與 intersection JSONL 到公開網站的 `docs/data/regions/area_4212533/`。
- 在公開 `region_manifest.json` 新增左營區，使選擇器與 Web adapter 能辨識並載入這個行政區。
- 使用者選擇左營區後，前端才呼叫既有 `/api/map-segments?district_area_id=area%2F4212533`。選擇器清空或切換行政區時，先清除舊圖層，再載入新行政區圖層。
- 沿用目前 Leaflet 樣式：未標註一般路段為灰色；已標註、高優先與目前選取道路仍沿用既有顏色與點擊行為。

## 邊界與資料一致性

行政區邊界不應裁切一條道路的幾何。只要路段被左營區 shard 收錄，就在左營區地圖顯示它的完整 LineString，避免使用者在交界處失去道路與路口的連續脈絡。

跨區道路以 `object_identity.nav_segment_key` 為唯一身分：

- 地圖資料合併或後續加入相鄰區背景時，先按這個 key 去重。
- 標註仍以同一個 key 儲存，因此道路不會因為出現在兩個行政區而產生兩份標註。
- 左營區的清單與可指派工作仍只使用左營區 shard；本次不預載任何相鄰區道路。若日後需要邊界視覺脈絡，可另加淡色、不可指派的相鄰區背景圖層，但它不擴張左營區任務範圍。

## 錯誤處理與效能

- Manifest 或 shard 缺失時，沿用目前 adapter 的明確載入錯誤，不顯示部分或誤導性的道路圖層。
- 維持一次只載入目前選取行政區；不要在未選區、初始載入或背景預取時載入左營資料。
- 保留 `mapRequestId` 的競態保護，避免使用者快速切換區域時由較慢的舊請求覆蓋新圖層。

## 驗證

新增或調整 adapter 測試，確認左營區可載入、`/api/map-segments` 回傳 2351 筆且帶有 LineString 幾何；確認未提供 district id 時仍不回傳地圖路段。執行既有 `node docs/test_annotation_model.mjs`、`node docs/test_web_adapter.mjs`，以及 `git diff --check`。

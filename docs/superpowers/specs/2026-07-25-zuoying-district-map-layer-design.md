# 左營區完整道路地圖圖層設計

## 目標與範圍

當使用者在 LanePilot 網頁標註工具選擇左營區時，地圖要顯示左營區完整道路網（灰色為未標註的一般路段），以方便組員直接在地圖上挑選並標註道路。使用者也能額外勾選多個行政區作為背景路網，以確認跨區道路與標註情況。未選行政區時不載入任何道路圖層，避免初始載入與地圖互動承受不必要的成本。

本次只增加左營區的資料、按選區載入行為與背景行政區多選；不改變既有路段清單、搜尋、篩選與標註任務的行政區範圍。

## 資料與載入設計

- 使用既有私有輸出中的左營區 shard：`area/4212533`（2351 個路段、1519 個路口），同步其 segment 與 intersection JSONL 到公開網站的 `docs/data/regions/area_4212533/`。
- 在公開 `region_manifest.json` 新增左營區，使選擇器與 Web adapter 能辨識並載入這個行政區。
- 「標註／清單區域」維持單選。使用者選擇左營區後，前端才呼叫既有 `/api/map-segments?district_area_id=area%2F4212533` 作為主圖層；選擇器清空或切換行政區時，先清除舊主圖層，再載入新行政區圖層。
- 新增「地圖背景區」核取清單，可同時勾選零個或多個已同步資料的行政區。每一區在勾選時才呼叫自己的 `/api/map-segments`，取消勾選時自地圖移除；已載入資料可在同一工作階段快取。
- 主圖層沿用目前 Leaflet 樣式：未標註一般路段為灰色；已標註、高優先與目前選取道路仍沿用既有顏色與點擊行為。
- 背景圖層維持相同狀態色（灰／綠／橘），但以較細線條、較低透明度與降低飽和度顯示，形成灰色蒙版感。它們保留視覺上的標註資訊，卻不會與目前標註區混淆。

## 邊界與資料一致性

行政區邊界不應裁切一條道路的幾何。只要路段被左營區 shard 收錄，就在左營區地圖顯示它的完整 LineString，避免使用者在交界處失去道路與路口的連續脈絡。

跨區道路以 `object_identity.nav_segment_key` 為唯一身分：

- 主圖層與多個背景圖層合併時，先按這個 key 去重，且主圖層優先；背景圖層不可重複覆蓋主圖層道路。
- 標註仍以同一個 key 儲存，因此道路不會因為出現在兩個行政區而產生兩份標註。
- 左營區的清單與可指派工作仍只使用左營區 shard；背景區只提供道路與標註狀態的地圖脈絡，不擴張左營區任務範圍，也不加入左營區搜尋結果。

## 錯誤處理與效能

- Manifest 或 shard 缺失時，沿用目前 adapter 的明確載入錯誤，不顯示部分或誤導性的道路圖層。
- 不要在未選區、初始載入或背景預取時載入任何道路資料；主區與每一個背景區都必須在使用者選擇或勾選後才載入。
- 保留 `mapRequestId` 的競態保護，避免使用者快速切換區域時由較慢的舊請求覆蓋新圖層。

## 驗證

新增或調整 adapter 與前端測試，確認左營區可載入、`/api/map-segments` 回傳 2351 筆且帶有 LineString 幾何；確認未提供 district id 時仍不回傳地圖路段。測試主區與多個背景區同時顯示時的去重、主圖層樣式優先權及背景狀態色。執行既有 `node docs/test_annotation_model.mjs`、`node docs/test_web_adapter.mjs`，以及 `git diff --check`。
